# R5 Hybrid Cinematic Fidelity Upgrade

## Purpose

R5 is the corrective visual-fidelity pass for the Convalt Energy interactive 3D landing experience. It keeps the R4.1 deterministic visual-development baseline but changes the runtime and asset strategy from one fixed mid-poly GLB per chapter to a **quality-aware hybrid hero system**.

The goal is not to turn browser assets into CAD. The goal is to make the camera-visible moments read like credible, premium energy/infrastructure visualization while keeping the contractual real-time performance target defensible.

## What was adopted from the external review

The following recommendations were selected because they fit the existing Convalt architecture and the SOW:

- quality-tier-aware hero loading rather than one asset for every device;
- current/adjacent chapter streaming so distant scenes are not kept hot;
- denser camera-visible hero moments and simplified connecting geometry;
- GPU instancing for repeated solar modules;
- progressive preloading through the existing AssetManager;
- shared PBR materials and aggressive draw-call control;
- camera-aware negative-space composition so models do not collide with chapter copy;
- strict triangle, draw-call, file-size and DPR budgets;
- adaptive resolution as the first performance governor rather than deleting authored geometry at runtime.

## What was deliberately not copied verbatim

Several example snippets in the review were architecture sketches, not safe drop-ins:

- The proposed `InstancedSolarField` populated matrices in `useMemo` while the ref was still null. R5 uses `useLayoutEffect`, so instance matrices are applied after the WebGL objects exist.
- Per-frame React `setState` hero activation was not adopted. The existing store already maintains `renderFrom`, and StoryWorld mounts only current + next scenes; this is cheaper and avoids React render churn inside `useFrame`.
- A new `THREE.LOD` manager was not added just to satisfy a pattern. R5 selects `/models/r5/high` or `/models/r5/medium` before loading, which avoids holding multiple LOD GLBs in GPU memory. The camera distances inside a chapter are narrow enough that device-tier LOD is the better trade.
- ScrollTrigger/virtual-scroll replacement was not adopted. The approved product behavior is interaction-driven, one chapter at a time (wheel, swipe, keyboard, progress dots), not a long flat scrolling page. The current GSAP chapter tween remains the timeline source of truth.
- Global opacity mutation across shared cached materials was not adopted. SceneAsset continues to clone per-instance materials before fading them.

## R5 asset tiers

### Medium

Designed for integrated GPUs and mid-range laptops. It retains R4.1 scene structure but adds facade articulation, machinery, switchyard detail, HVAC, rollers, sorters and other object-level cues. Anti-aliasing is now always requested at WebGL context creation.

### High

Designed for higher-headroom GPUs. It adds denser manufacturing equipment, rooftop mechanical/fan banks, smoother turbine components, denser solar-generation and switchyard detail, expanded recycling plant equipment and extra architectural trim.

The generation script emits both tiers to:

```text
public/models/r5/high/*.glb
public/models/r5/medium/*.glb
public/models/r5/manifest.json
```

## Key visual defects corrected

### 1. Jagged silhouettes

R4.1 created the WebGL context with `antialias: false` whenever the initial React quality state was `medium`. Because context attributes cannot be upgraded later, a machine that was subsequently detected as high quality could still remain non-antialiased. R5 requests MSAA unconditionally for both WebGL tiers and then governs DPR adaptively.

### 2. Ground checker / tiled shading

R4.1 used a vignette-style AO texture on large repeated Ground/Asphalt/Concrete/Facade surfaces. When repeated over large planes this produced visible square/patch shading. R5 disables that AO usage on repeating macro surfaces and relies on direct lighting, shadows, roughness and normal breakup instead.

### 3. Flat material response

R5 raises anisotropic filtering on embedded PBR textures (bounded by device capability), tightens metal/glass roughness response and enables a single bounded directional shadow map on both high and medium tiers.

### 4. Text/model collisions

Desktop scene transforms were re-authored to preserve a safe copy column. Left-aligned chapters push the hero environment right; right-aligned chapters push it left. The 3D remains visually dominant without sitting underneath the large editorial headings.

## Asset metrics generated by the R5 authoring pass

The deterministic authoring script validates both tiers against per-scene budgets. On the reference generation pass:

- **Medium:** 192,748 triangles total across six GLBs, ~14.83 MiB total.
- **High:** 262,392 triangles total across six GLBs, ~16.37 MiB total.

Only current/adjacent scenes are retained around a chapter transition, so total repository triangles are not the active GPU triangle count.

## Renderer budgets

- High: DPR 1.00–1.75, max 110 draw calls, 340k active triangles.
- Medium: DPR 0.85–1.35, max 95 draw calls, 220k active triangles.
- The performance governor samples runtime FPS and reduces resolution before asset fidelity.
- Quality can still be forced for QA with `?quality=high`, `?quality=medium`, or `?quality=fallback`.

## Acceptance evidence

The CI release gate now requires:

1. deterministic generation of 12 R5 GLBs (6 high + 6 medium);
2. TypeScript success;
3. R5 manifest / file / triangle / mesh-group / renderer-contract validation;
4. Next.js production build success;
5. Vercel token verification and production deployment.

The contractual **60 fps on a named mid-range laptop** still requires a physical benchmark capture. The repository includes the existing benchmark instrumentation for that final hardware evidence.
